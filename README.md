
# Дипломный практикум в Yandex.Cloud - Инфраструктура

Дипломный практикум в Yandex.Cloud - Инфраструктура

========================================================

## Описание проекта

Данный проект представляет собой инфраструктуру Yandex Cloud, развертываемую с помощью инструмента Terraform в соответствии с принципами Infrastructure as Code (IaC). Инфраструктура включает сервисный аккаунт с набором ролей и S3-совместимое хранилище для хранения состояния Terraform.

Проект реализован в виде модульной архитектуры, что обеспечивает переиспользование компонентов, разделение ответственности и упрощение поддержки.

## Цели и задачи

- Автоматизация развертывания инфраструктуры Yandex Cloud
- Обеспечение воспроизводимости и версионирования инфраструктуры
- Разделение инфраструктуры на логические модули для удобства поддержки
- Соблюдение принципов безопасности при работе с учетными данными

## Архитектура

Проект следует модульной архитектуре Terraform с тремя уровнями:

```plaintext
devops-diplom-infra/
├── backend/                    # Главный файл конфигурации (точка входа)
│   ├── main.tf                 # Конфигурация провайдера и вызов модулей
│   ├── variables.tf            # Глобальные переменные
│   ├── outputs.tf              # Выходные параметры
│   ├── terraform.tfvars        # Значения переменных (не в VCS)
│   └── terraform.tfstate       # Состояние инфраструктуры (не в VCS)
├── modules/
│   ├── iam/                    # Модуль управления IAM
│   │   ├── main.tf             # Ресурсы: SA, data source, роли
│   │   ├── variables.tf        # Входные параметры модуля
│   │   ├── outputs.tf          # Выходные параметры
│   │   └── versions.tf         # Зависимости провайдера
│   └── storage/                # Модуль управления хранилищем
│       ├── main.tf             # Ресурсы: бакет, ключ доступа
│       ├── variables.tf        # Входные параметры модуля
│       ├── outputs.tf          # Выходные параметры
│       └── versions.tf         # Зависимости провайдера
├── .gitignore                  # Исключения для Git
└── README.md                   # Документация
```

## Используемые технологии

| Технология | Назначение |
|---|---|
| Terraform >= 1.3.0 | Оркестрация инфраструктуры (IaC) |
| Yandex Cloud Provider | Провайдер для управления ресурсами Yandex Cloud |
| S3-совместимое хранилище | Хранение состояния Terraform |
| Git | Контроль версий конфигурации |

## Описание модулей

### Модуль IAM (`modules/iam/`) 

Модуль отвечает за управление сервисными аккаунтами и их ролями в Yandex Cloud.

**Функциональность:**
- Создание нового сервисного аккаунта или использование существующего (управляется переменной `create_sa`)
- Назначение набора ролей в указанной папке Yandex Cloud
- Поддержка динамического назначения произвольного списка ролей

**Ресурсы:**
- `yandex_iam_service_account` — сервисный аккаунт (создается при `create_sa = true`)
- `data.yandex_iam_service_account` — загрузка существующего аккаунта (при `create_sa = false`)
- `yandex_resourcemanager_folder_iam_member` — назначение каждой роли из списка

**Ключевой паттерн:** Условное создание ресурса через `count` + data source позволяет модулю работать в двух режимах без дублирования кода.

**Входные параметры:**

| Параметр | Тип | Описание | По умолчанию |
|---|---|---|---|
| `sa_name` | string | Имя сервисного аккаунта | — |
| `folder_id` | string | ID папки Yandex Cloud | — |
| `roles` | list(string) | Список ролей для назначения | `["editor", "storage.editor"]` |
| `create_sa` | bool | Создавать новый аккаунт | `false` |

**Выходные параметры:**

| Параметр | Описание |
|---|---|
| `service_account_id` | ID сервисного аккаунта |

### Модуль Storage (`modules/storage/`)

Модуль отвечает за создание S3-совместимого хранилища и ключей доступа.

**Функциональность:**
- Создание бакета с уникальным именем
- Генерация статического ключа доступа для S3-совместимого API
- Настройка версионирования объектов
- Возможность принудительного удаления бакета с объектами

**Ресурсы:**
- `yandex_storage_bucket` — S3-бакет с версионированием
- `yandex_iam_service_account_static_access_key` — статический ключ доступа

**Входные параметры:**

| Параметр | Тип | Описание | По умолчанию |
|---|---|---|---|
| `bucket_name` | string | Уникальное имя бакета | — |
| `service_account_id` | string | ID сервисного аккаунта | — |
| `enable_versioning` | bool | Включить версионирование | `true` |
| `force_destroy` | bool | Разрешить удаление с объектами | `true` |

**Выходные параметры:**

| Параметр | Описание |
|---|---|
| `bucket_name` | Имя созданного бакета |
| `access_key` | Access Key для S3 API |
| `secret_key` | Secret Key для S3 API |

### Backend (`backend/`)

Главный файл конфигурации, который orchestrates все модули.

**Функциональность:**
- Настройка провайдера Yandex Cloud
- Вызов модулей IAM и Storage
- Передача выходных параметров одного модуля в другой (dependency injection)

**Назначаемые роли:**
| Роль | Описание |
|---|---|
| `editor` | Полный доступ к ресурсам в папке |
| `storage.editor` | Управление хранилищем Object Storage |
| `container-registry.admin` | Администрирование Yandex Container Registry |
| `dns.editor` | Управление DNS-записями |

## Безопасность

- Чувствительные данные (`token`, `cloud_id`, `folder_id`, ключи доступа) помечены как `sensitive`
- Файлы `.tfstate` и `.tfvars` исключены из системы контроля версий (`.gitignore`)
- Статические ключи генерируются автоматически при создании бакета
- Версионирование бакета обеспечивает защиту от потери состояния

## Требования

- Terraform >= 1.3.0
- Аккаунт Yandex Cloud
- Токен IAM для аутентификации
- Сформированный сервисный аккаунт (или разрешение на создание)

## Быстрый старт

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd devops-diplom-infra
```

### 2. Настройка переменных

Создайте файл `backend/terraform.tfvars` со значениями:

```hcl
yandex_token     = "your-yandex-token"
cloud_id         = "your-cloud-id"
folder_id        = "your-folder-id"
sa_name          = "your-service-account-name"
bucket_name      = "tfstate-diplom"
```

Получить токен можно в [консоли Yandex Cloud](https://console.yandex.cloud/iam/token).

### 3. Инициализация

```bash
cd backend
terraform init
```

### 4. Применение

```bash
terraform plan    # Предпросмотр изменений
terraform apply   # Развертывание инфраструктуры
```

### 5. Проверка

После успешного применения будут доступны выходные параметры:

```bash
terraform output
```

### 6. Уничтожение

```bash
terraform destroy
```

## Использование ключей доступа

Полученные ключи можно использовать для работы с хранилищем через S3-совместимый API:

```bash
export ACCESS_KEY_ID=<access_key>
export SECRET_ACCESS_KEY=<secret_key>
export DEFAULT_REGION=ru-central1-d

# Пример: список объектов в бакете
aws --endpoint-url https://storage.yandexcloud.net s3 ls s3://<bucket-name>/
```

## Структура состояний

Состояние инфраструктуры хранится в файле `backend/terraform.tfstate`. Для работы в команде рекомендуется использовать удаленный бэкэнд (Yandex Object Storage, S3, Terraform Cloud и т.д.).

В текущей реализации бэкэнд настроен локально. Для переключения на удалённый бэкэнд добавьте в `backend/main.tf`:

```hcl
terraform {
  backend "s3" {
    bucket         = "tfstate-diplom"
    key            = "infrastructure/terraform.tfstate"
    region         = "ru-central1"
    access_key     = "..."
    secret_key     = "..."
    encrypt        = true
  }
}
```

## Визуализация инфраструктуры

Для визуализации зависимостей между ресурсами:

```bash
terraform graph | dot -Tpng > infrastructure.png
```

## Известные ограничения

- Бэкэнд настроен на локальное хранение состояния
- Сервисный аккаунт используется существующий (`create_sa = false`)
- Роли назначаются на уровне папки (`folder`), а не облака (`cloud`)
